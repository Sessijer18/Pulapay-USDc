01
Design Context

Pourquoi Pulapay
doit être différent.

Le design de Pulapay n'est pas un exercice stylistique. Il répond à un problème réel : l'infrastructure financière africaine est fragmentée, l'UX des apps existantes est construite pour l'Occident. Pulapay doit donner l'impression que quelqu'un a enfin compris.

◎
Principe 01
Radical Simplicity
L'utilisateur comprend le produit en moins de 5 secondes. Jamais de concept à apprendre. Jamais de question sans réponse visible. Chaque écran a une seule action principale.
⊟
Principe 02
One Balance System
L'utilisateur voit toujours un seul solde. Peu importe le rail utilisé en backend (Mobile Money, USDC, carte). La complexité est invisible. Jamais de "choisir un réseau".
◷
Principe 03
Invisible Infrastructure
Mobile Money, stablecoins, blockchain, rails de paiement — ce sont nos problèmes, pas ceux de l'utilisateur. L'UI ne doit jamais exposer ces termes au grand public.
Philosophie centrale
"Envoyer de l'argent doit être aussi simple
qu'envoyer un message."
— Si l'utilisateur réfléchit, on a échoué.
  • 🎯 Audience cible : Africains 18–35 ans, digital-native, entrepreneurs, freelances, créateurs. Ils utilisent Mobile Money quotidiennement et veulent quelque chose qui fonctionne simplement.
  • 📱 Mobile-first absolu : Le frontend est d'abord pensé pour smartphone. Chaque composant est designé pour une main, un pouce, une connexion parfois lente.
  • 🤝 Confiance visuelle : L'argent est émotionnel. Le design doit transmettre soulagement, clarté, et contrôle — jamais l'urgence ni la peur.
  • ✦ Références UX : Cash App (boldness + simplicité), Revolut (modernité), Apple Wallet (confiance par la retenue). Pas une banque avec meilleure UI.

06
Motion Design

Le mouvement avec intention.

Chaque animation a une raison fonctionnelle. Elle guide, confirme, rassure. Jamais pour décorer. L'argent demande du sérieux — pas des confettis.

⚡
Micro-feedback
dur: 150ms · ease-out
Hover, press, tap. Confirmation immédiate que l'action a été enregistrée.
✓
Succès Transaction
dur: 300ms · spring(0.34,1.56,0.64,1)
Rebond léger sur la confirmation. Célèbre sans surjouer.
→
Navigation
dur: 250ms · ease-in-out
Slide horizontal. Envoi = droite. Retour = gauche. Logique directionnelle.
Loading Skeleton
dur: 1.5s · ease-in-out · loop
Pulsation douce pendant le chargement du solde. Jamais de spinner agressif.
↑
Page Load Reveal
dur: 400ms · stagger: 60ms
Éléments qui apparaissent du bas vers le haut en cascade. Un seul moment orchestré par écran.
✗
À ne jamais faire
No: flash · bounce excessif · spin · parallax · confetti
L'argent = sérieux. Pas d'effets spectaculaires. prefers-reduced-motion toujours respecté.

Chaque flow est une mission utilisateur. Chaque étape a une action principale visible. Jamais plus de 5 étapes pour compléter une action.

Autres flows essentiels
Flow 3
Recevoir de l'argent
QR Code personnel · Lien de paiement pulapay.com/pay/slug · Partage via WhatsApp/SMS · Notification push automatique
Flow 4
Demander un paiement
Saisie montant + note optionnelle → Génération lien/QR → Share sheet native → Tracking statut paiement
Flow 5
Cash Out (Retrait)
Sélection méthode : Mobile Money ou wallet externe → Saisie montant → Confirmation avec frais → Traitement → Succès
Flow 6
Historique transactions
Liste infinie chronologique · Filtre par type/date · Détail par transaction : ID, timestamp, source, destination, statut

Gestion du compte
Profil · Sécurité · Recovery options · Devices · Notifications · KYC status
Gestion d'erreurs
Chaque flow → états d'erreur
Solde insuffisant · Erreur réseau · Paiement échoué · Timeout. Messages : clairs, humains, rassurants. Jamais de code d'erreur technique visible.
09
Do / Don't

Ce que Pulapay est et n'est pas.

Règles non-négociables pour chaque décision design. Si tu hésites, relis la phrase : "Si ça ressemble à une fintech qui essaie d'être cool, ce n'est pas Pulapay."

✓ Pulapay fait ça
✓
Un seul solde visible, toujours en FCFA (ou devise locale)
✓
Une seule action principale par écran, hiérarchie visuelle claire
✓
Messages d'erreur en langage humain, rassurants
✓
Feedback immédiat sur chaque action (150ms max)
✓
Texte court, phrases directes, sans jargon
✓
Orange uniquement pour les CTA et accents critiques
✓
Vert uniquement pour les confirmations et entrées d'argent
✓
Loading states rassurants (skeleton, pas spinner)
✓
Product Sans pour l'UI, Times NR MT pour l'émotion
✓
Mobile-first, touch-friendly (tap target minimum 44×44px)
✗ Pulapay ne fait jamais ça
✗
Afficher "blockchain", "USDC", "stablecoin" à l'utilisateur
✗
Demander à l'utilisateur de choisir un réseau de paiement
✗
Codes d'erreur techniques visibles (ex: "Error 4029")
✗
Plus de 5 étapes pour compléter une action
✗
Gradients violets sur fond blanc (fintech générique)
✗
Animations non-fonctionnelles, confettis, effets spectaculaires
✗
Plusieurs soldes ou balances visibles simultanément
✗
CTA agressifs ("Télécharge MAINTENANT !!!")
✗
Texte trop petit (min 13px pour le corps, 11px pour les labels)
✗
Formulaires longs sans progression visible ni feedback

Règles de développement
RègleDétail
Touch targetsMinimum 44×44px pour tout élément interactif. Aucune exception sur mobile.
Contraste texteRatio minimum 4.5:1 pour le corps (WCAG AA). Blanc sur orange interdit pour le texte long.
prefers-reduced-motionToujours vérifier et désactiver les animations si demandé.
Montants financiersToujours formater avec séparateur de milliers. Jamais d'ambiguïté sur la devise. 247 500 FCFA pas 247500.
États de chargementSkeleton loader pour les montants, jamais de spinner seul sur le solde.
Gestion d'erreursMessage humain toujours. Code technique jamais visible. Toujours proposer une action de sortie.
Navigation mobileBottom nav bar. 3–4 items max. Tab Send toujours en premier.
Idempotency UIDésactiver les boutons de confirmation après le premier clic. Prévenir les doubles envois.
Dark / Light modeMVP : Light mode uniquement. Les sections hero et sidebar restent toujours dark.
InternationalisationPrévoir i18n dès le départ. Langues cibles : Français, Anglais, Fon (Bénin).
